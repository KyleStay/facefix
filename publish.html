STEP 02

Try it once on Facebook

  1. Extract the upload ZIP into a folder. Open chrome://extensions, enable Developer mode, choose Load unpacked, and select that folder.
  2. Reload Facebook, scroll down, switch away for a minute, then return. Check your position and the same visible posts. Repeat on a group or individual post.
  3. Open Facefix. Check that installed and page versions match. If disconnected, allow Facefix site access on Facebook and refresh Facebook once. The popup shows Facefix’s 4-second and 15-second protection windows, not Facebook’s private timers. Return-event counts should increase when signals are suppressed. Reload and Home-redirect counts can stay at zero if no such navigation was attempted.
  4. Check clicking Home, Back/Forward, manual Reload, typing a draft without submitting it, and scrolling. Pause protection, reset counters, and return again: counters should stay at zero.
  5. Resume protection and compare the installed popup with the included images. The screenshots show its initial zero-counter interface, not results from a Facebook session. Use them in the order below, or add your own real capture without names or private content.

After a failure, use Diagnostics and failure reports → Something went wrong, then review the local report. Verify export, clear, and the recording switch. If you find a regression, fix it before submission. Facefix reduces known refresh triggers; it cannot freeze every internal Facebook feed update.

STEP 03

Add a new item

  1. Open the Developer Dashboard in your existing publisher account.
  2. Click Add new item or New item, choose facefix-1.4.0-store.zip, and upload it.
  3. Check that the package shows Facefix — Keep My Place, version 1.4.0, and Manifest V3. Save the new extension ID for later.
Upload trouble?

“Cannot find manifest” usually means the wrong ZIP or an extra enclosing folder. Use the prepared store ZIP above. If your account has reached its item limit, use the dashboard's increase-request option. Verify your publisher email or complete any existing account requirements the dashboard identifies.

STEP 05

Paste the privacy answers

Open Privacy practices (sometimes labeled Privacy). These answers describe the bundled code, including its local processing.

Remote code: No. Select “No, I am not using remote code.” All executable extension code is in the uploaded ZIP; it downloads no code or configuration.

Data usage

Disclose Web history for local Facebook URL/navigation checks and User activity for local visibility, scroll, and interaction signals and aggregate counters, and Website content for local inspection of visible article positions and post links used to recover your place. In any explanation field, use the text below. Do not claim “no user data handled” merely because it stays on the device: Google's policy also covers local processing. No other data categories are used by this build.

Read and check the certifications that data is not sold or transferred outside allowed uses, not used for unrelated purposes, and not used for creditworthiness or lending decisions. These statements match this build.

Open that URL in a private/incognito window before submitting. It must show the policy without requiring sign-in. A local file path will not work in the store.

STEP 06

Help the reviewer test it

Open Test instructions. Do not provide your personal Facebook password. A reviewer needs their own authorized Facebook session to test feed behavior.

If the review team requests a recording or a dedicated test account, provide an authorized test setup through the dashboard. Never put credentials in the public repository.

STEP 07

Choose visibility and submit

  1. Open Distribution. For a normal public launch, choose Public, free access, and the regions you intend to support.
  2. Resolve any dashboard validation errors. Check the listing preview, privacy link, and contact details.
  3. Click Submit for Review. In the confirmation dialog, choose whether to publish automatically after approval or publish manually later.
  4. Confirm the submission and watch the dashboard and publisher email for the review result. Review timing varies; submission is not approval.

If you choose deferred publication, publish the approved item before its staging deadline. Google's current documentation gives a 30-day window after approval.
